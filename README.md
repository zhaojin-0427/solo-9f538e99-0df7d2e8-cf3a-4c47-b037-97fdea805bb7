# 共享电单车电池寿命分析

用 Flask + SQLite 做的电池随访台账、Kaplan–Meier 无故障概率页面，以及按机龄层加权的
试点组 / 非试点组故障率对比，帮助车队安排抽检并评估试点电池。

## 启动

```bash
docker compose up --build
```

打开 <http://localhost:8000>（可用 `APP_PORT` 改端口）。数据库保存在 `battery-data` 卷中，
容器以非 root 用户运行并带健康检查。

本地开发：

```bash
python3 -m pip install -r requirements.txt
python3 app.py            # 或 BATTERY_DB=/tmp/x.db python3 app.py
python3 -m pytest tests -q
```

## 使用流程

1. 在 **上传随访** 页提交随访 CSV（UTF-8 或 GB18030；可先下载模板）。
2. 在 **试点名单** 页提交名单 CSV（电池号、UTC 试点开始日）；名单可先于随访登记，
   同号再次上传即为更正。
3. 在 **寿命分析** 页选择截止日（UTC），查看每个发生过故障的机龄对应的在险数、故障数
   和 KM 无故障概率。
4. 在 **试点对比** 页选择含首尾的 UTC 日期范围，查看分层随访电池日、故障数和
   按共同机龄层加权的两组故障率。
5. **台账** 页查看当前生效的每块电池记录。

### 随访 CSV 格式

必需列（也接受对应中文表头）：

| 列 | 含义 |
| --- | --- |
| `battery_no` | 电池号，文件内必须唯一 |
| `activation_date` | 启用日（UTC，`YYYY-MM-DD`） |
| `followup_start` | 随访首日 |
| `followup_end` | 随访末日 |
| `outcome` | `failure` / `censored`（也接受“故障 / 正常结束”） |

可选 `action` 列：`insert` / `update` / `delete`（或“补录 / 更正 / 删除”）。
留空时自动判断：新电池号新增，已存在则视为更正（同号旧记录被覆盖）。

日期接受 `YYYY-MM-DD`、`YYYY/MM/DD`、ISO 8601 时间戳；带时区的时间会先换算为 UTC 再取日期。

### 试点名单 CSV 格式

必需列（也接受对应中文表头）：`battery_no`（电池号）、`pilot_start`（试点开始日，UTC）。
可选 `action` 列，语义与随访 CSV 相同（留空自动判断：不存在则新增，已存在则更正）。
未在名单中的电池，其随访一律计入非试点组。

### 校验规则

* 整份文件先校验再写入；任一行出错则整份拒绝，数据库和已有曲线、对比结果都不受影响。
* 同一文件内电池号重复、日期缺失/非法、随访首日晚于末日、随访末日早于首日都会报错并给出行号。
* 同一电池号的更正覆盖旧值，删除则从曲线中移除。

## 统计口径

### 寿命分析

* 机龄 = 随访日期 − 启用日，按整天计算。
* 随访截到所选截止日：尚未入组的电池（随访首日晚于截止日）不计；
  截止当天发生的故障照计；截止当天结束随访的电池仍计入当天在险数。
* 同一机龄先入组再计故障；某机龄当天结束时先计入在险数再删失。
* 截止日后的故障按该日删失处理。
* KM 无故障概率逐故障机龄相乘：`S(t) = ∏ (1 − d_i / n_i)`，只列出发生故障的机龄。

### 试点对比

* 日期范围含首尾两天（UTC）。
* 每个随访日按当天机龄是否满 180 天分层（`< 180 天` / `≥ 180 天`），
  按当天是否已到该电池的试点开始日分组（试点组 / 非试点组）。
* 跨层、跨组的随访在边界日切开统计，全程不逐日展开。
* 故障当天计一天随访；故障只记入当天所在的组和层。
* 只取两组都有随访的机龄层，按每层两组合计随访电池日占这些层总随访电池日的比例加权，
  给出两组每千随访电池日的加权故障率，差值 = 试点组 − 非试点组。
* 没有共同机龄层时提示无法比较。

## 存储结构

| 表 | 用途 |
| --- | --- |
| `battery_ledger` | 台账：每块电池当前一条记录 |
| `battery_summary` | 每块电池 1 条汇总记录（更正原地覆盖并递增 `revision`） |
| `battery_summary_usage` | 每块电池汇总记录的终身用量，补录/更正/删除各计 1 次，上限 6 条 |
| `summary_counts` | 按启用日与天偏移预聚合的计数，**寿命分析页只读这张表** |
| `pilot_roster` | 试点名单：每块电池当前一条记录（同号更正原地覆盖） |
| `battery_segments` | 每块电池的随访分段（每段完全落在同一组、同一机龄层），**试点对比页只读这张表** |
| `import_batches` | 随访导入批次统计 |
| `roster_batches` | 名单导入批次统计 |

每块电池的补录、更正、删除合计最多写入 6 条汇总记录；超出时整份文件被拒绝，
已有曲线不受影响。台账、汇总记录、用量计数、聚合计数和分段汇总在同一个 SQLite 事务中写入；
名单导入同样把名单行、受影响电池的分段重算和批次记录放在同一事务里。
名单和随访并发导入时，每批原数据和汇总一起生效；导入失败整体回滚，
分析页仍可按原有汇总查询（即使台账表本身不可用也不影响曲线和对比）。
导入只重算本批涉及电池的分段；统计查询只读汇总表，不逐日展开随访。
升级后首次启动会一次性为卷里已有的随访回填分段汇总，原数据直接纳入对比统计。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/survival?cutoff=YYYY-MM-DD` | 寿命分析页 |
| GET | `/pilot?start=YYYY-MM-DD&end=YYYY-MM-DD` | 试点对比页（含首尾） |
| GET/POST | `/upload` | 上传随访页面 / 导入随访 CSV |
| GET/POST | `/roster` | 试点名单页面 / 导入名单 CSV |
| GET | `/ledger` | 当前台账 |
| GET | `/template.csv` | 下载随访模板 |
| GET | `/roster-template.csv` | 下载名单模板 |
| GET | `/healthz` | 健康检查 |
